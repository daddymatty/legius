# Інтеграція форми сайту з Zoho CRM — стан і запуск

Worker уже написаний сесією сайту: `worker/lead-telegram.js`
(форма → Telegram-група + Заявка в Zoho CRM). Zoho-гілка вмикається
автоматично, коли задані секрети `ZOHO_CLIENT_ID`, `ZOHO_CLIENT_SECRET`,
`ZOHO_REFRESH_TOKEN`. Токен-флоу, кеш на 50 хв, EU-ендпоінти — все вже
в коді правильно.

Стан CRM звірено через API-конектор 09.09.2026.

## Що зроблено CRM-сесією 09.09.2026

- Звірено API-імена полів модуля Заявки (`Leads`): `Last_Name`
  (обов'язкове), `First_Name`, `Phone`, `Email`, `Description`,
  `Lead_Status`, `Lead_Source`.
- Виправлено воркер: `Lead_Source: "Website"` → `"Сайт"` і додано
  явний `Lead_Status: "Нова"` (без нього статус залежав би від дефолту
  поля). ⚠️ Picklist-поля приймають **display-значення як в інтерфейсі**
  (укр.); невідоме значення Zoho пише сирим рядком, і заявка випадає
  з фільтрів/канбану — перевірено на практиці в липні 2026.

## Що лишилося (чек-лист запуску)

1. **CRM (власник, 1 хв):** Модулі → Заявки → макет → поле
   «Заявка - источник» (Lead Source) → перейменувати значення
   **«Загрузка из Интернет» → «Сайт»**. Поки цього нема, заявки
   створяться, але джерело буде поза списком.
2. **Zoho Self Client (власник, 5 хв):**
   - [api-console.zoho.eu](https://api-console.zoho.eu) → Add Client →
     **Self Client** → отримати Client ID + Client Secret.
   - Вкладка Generate Code: scope `ZohoCRM.modules.leads.CREATE`,
     duration 10 min → згенерувати **grant code** (живе хвилини —
     робити безпосередньо перед кроком 3).
3. **Обмін на refresh token** (одноразово, будь-де з curl):
   ```bash
   curl -s -X POST https://accounts.zoho.eu/oauth/v2/token \
     -d grant_type=authorization_code \
     -d client_id=CLIENT_ID -d client_secret=CLIENT_SECRET \
     -d code=GRANT_CODE
   # відповідь містить "refresh_token" — він безстроковий
   ```
   ⚠️ Тільки `.eu` (акаунт у європейському ДЦ); `.com` дасть invalid client.
4. **Секрети воркера** (сесія сайту або власник у Cloudflare dashboard):
   `wrangler secret put ZOHO_CLIENT_ID / ZOHO_CLIENT_SECRET /
   ZOHO_REFRESH_TOKEN`. У git секрети не потрапляють.
5. **Тест:** надіслати форму з сайту → перевірити в crm.zoho.eu:
   модуль Заявки, запис зі статусом «Нова», джерело «Сайт», ім'я/телефон/
   текст у своїх полях. CRM-сесія може звірити запис через конектор.
   Тестову заявку видалити.

## Довідка для дебагу

| Симптом | Причина/дія |
|---|---|
| `invalid client` при обміні токена | використано `.com` замість `.eu` |
| `401 INVALID_TOKEN` на POST /Leads | access token протух — воркер сам оновить при наступному виклику |
| `INVALID_DATA` + api_name у details | прибрати вказане поле; мінімальний валідний payload — `Last_Name` + `Lead_Status` |
| Заявка є, але не видно у фільтрі «Нова» | у picklist пішло не-display значення — див. ⚠️ вище |

Дублікати Zoho для Leads не блокує — повторний сабміт форми створить
другу заявку, це прийнятно.

## Фаза 2 (після запуску базового потоку): автопривітання

- **Email** з подякою на адресу з форми — шле воркер після створення заявки.
- **Telegram**: бот не може написати людині першим (правило платформи).
  Патерн: сторінка «Дякуємо» → кнопка `t.me/<бот>?start=<id заявки>`;
  хто натиснув — тому бот шле привітання («Ваш адвокат — N, зв'яжеться
  до кінця робочого дня»). Вебхук бота — той самий воркер.
- Тексти привітань готує CRM-сесія.
