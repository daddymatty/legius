# Zoho CRM для LEGIUS — покрокове налаштування

Розраховано на Zoho CRM **Free Edition** (до 3 користувачів, безстроково).
Пошта вже працює на Zoho Mail Free (домен legius.com.ua).

## Що дає і чого НЕ дає Free-версія (щоб не було сюрпризів)

**Є:** Ліди, Контакти, Компанії (Accounts), Deals (перейменуємо на «Справи»),
Задачі/Події/Дзвінки, календар, перейменування модулів, редагування етапів
(Stage) угод, до 5 000 записів, мобільний застосунок, інтеграція з іншими
Zoho-сервісами.

**Немає:** workflow-автоматизацій, кастомних полів (майже), кастомних модулів,
Zia AI, розширених звітів (ліміт ~5), Blueprint. Якщо колись впремося —
Standard коштує недорого, але поки Free повністю покриває задачу
«робочий простір адвокатів».

## Крок 1. Реєстрація CRM на існуючий Zoho-акаунт

> ⚠️ **Важливо: дата-центр.** Zoho тримає акаунти в різних дата-центрах
> (zoho.**com**, zoho.**eu**, …). CRM треба відкривати в тому самому ДЦ, де
> вже живе пошта. Подивіться на адресний рядок, коли відкрита пошта:
> `mail.zoho.eu` → йдіть на `crm.zoho.eu`; `mail.zoho.com` → `crm.zoho.com`.
> Якщо просто залогінитися існуючим акаунтом — Zoho сам приведе куди треба.

1. Увійдіть у Zoho під акаунтом **адміністратора пошти** (той, хто керує
   доменом legius.com.ua) — саме він стане Super Admin у CRM.
2. Відкрийте `crm.zoho.eu` (або `.com` — за вашим ДЦ) → кнопка
   **Get Started / Access Zoho CRM**. Оскільки акаунт уже існує, реєстрації
   як такої не буде — Zoho створить CRM-організацію на цьому акаунті.
3. На стартовому екрані:
   - **Company name:** `LEGIUS`
   - НЕ ведіться на тріал Enterprise, якщо запропонують: тріал не страшний
     (через 15 днів сам стане Free), але можна одразу обрати
     **Free Edition** — внизу дрібним шрифтом або через
     `Settings → Billing → Downgrade to Free`.

## Крок 2. Базові налаштування організації

`Settings (шестерня) → General → Company Settings`:

- **Time Zone:** `(GMT+2:00) Europe/Kyiv`
- **Currency:** `UAH — українська гривня` (Currency настройки — у
  `Company Settings → Currencies`; у Free мультивалютності немає, ставимо
  домашню валюту одразу — потім її змінити важко)
- **Fiscal Year:** січень
- Логотип LEGIUS (можна взяти з сайту) — `Company Settings → Logo`.

## Крок 3. Користувачі (3 партнери)

`Settings → Users and Control → Users → + New User`:

- Додайте двох інших партнерів на їхні скриньки `@legius.com.ua`.
- Роль: `CEO` або `Manager` — у юрфірмі з 3 партнерів немає сенсу в
  ієрархії; найпростіше всім дати роль CEO і профіль Administrator,
  тоді всі бачать усе.
- Кожен отримає лист-запрошення на пошту → приймають → готово.
- office@ НЕ робимо користувачем (місця лише 3) — ця скринька буде
  джерелом заявок, а не робочим місцем.

## Крок 4. Deals → «Справи» з юридичними етапами

### 4.1. Перейменування модуля

`Settings → Customization → Modules and Fields → Deals → (⋮ або Module
Settings) → Rename`:

- **Plural:** `Справи`
- **Singular:** `Справа`

Заодно можна перейменувати поле `Deal Name` → `Назва справи`
(редагування ярликів полів: відкрити модуль → Fields → Edit Properties).

### 4.2. Етапи справи (поле Stage)

`Modules and Fields → Справи → Fields → Stage → Edit Properties
(або в Layout-редакторі → поле Stage → налаштування picklist)`.

Замінити стандартні продажні етапи на:

| Етап | Категорія (Forecast) | Ймовірність |
|---|---|---|
| Консультація | Open | 10% |
| Договір | Open | 30% |
| Провадження | Open | 50% |
| Суд | Open | 70% |
| Виконання | Open | 90% |
| Закрито (успішно) | **Closed Won** | 100% |
| Закрито (відмова/програно) | **Closed Lost** | 0% |

> Zoho вимагає, щоб існував хоча б один етап категорії Closed Won і один
> Closed Lost — тому «Закрито» технічно розбивається на два. У щоденній
> роботі це навіть зручно: одразу видно результат справи. Ймовірності —
> формальність (у Free немає прогнозів), можна не зважати.

Старі етапи (Qualification, Needs Analysis…) — видалити; Zoho спитає, на
який етап перенести існуючі записи (їх поки нема, тож просто видаляємо).

### 4.3. Поля справи

У Free кастомні поля практично недоступні, тому працюємо ярликами
наявних полів (Edit Properties → Field Label):

- `Amount` → `Сума гонорару`
- `Closing Date` → `Очікувана дата завершення`
- `Next Step` → `Наступна дія`
- Зайві продажні поля (Lead Source можна лишити — корисно знати, звідки
  клієнт) — просто прибрати з макета (Layout: перетягнути в Unused Fields).
- Номер справи в суді, суд, суддя — поки що в поле `Description` або в
  назву справи за шаблоном: `Прізвище клієнта — суть — № провадження`.

## Крок 5. Ліди → вхідний кошик «Заявки»

`Modules and Fields → Leads → Rename`: **Plural:** `Заявки`,
**Singular:** `Заявка`.

Логіка роботи:

1. Все вхідне (форма сайту — пізніше через Worker, дзвінки, листи на
   office@) заводиться як **Заявка**. Мінімум полів: ім'я, телефон/email,
   суть питання (Description).
2. Партнер дивиться кошик заявок → або сміття (Delete / статус
   `Junk Lead`), або **Convert** (кнопка у записі): Zoho сам створить
   Контакт (+Компанію, якщо є) і одразу Справу на етапі «Консультація».
3. Поле `Lead Status` теж можна українізувати: `Нова`, `В опрацюванні`,
   `Записаний на консультацію`, `Не наш профіль`, `Спам`.

## Крок 6. Задачі, календар, зустрічі — на перший план

### 6.1. Порядок вкладок

`Settings → Customization → Modules and Fields → Organize Modules`
(або просто перетягнути вкладки): порядок для юрфірми:

1. **Home** (Головна)
2. **Activities / Tasks** (Задачі)
3. **Calendar** (якщо вкладки нема — календар живе за іконкою 📅 угорі
   праворуч; активності = вкладка Activities)
4. **Справи**
5. **Контакти**
6. **Заявки**
7. **Компанії**

### 6.2. Приховати зайве

Там само (Organize Modules) зняти галочки з непотрібних продажних модулів:
`Forecasts`, `Campaigns`, `Products`, `Quotes`, `Sales Orders`,
`Invoices`, `Price Books`, `Cases`, `Solutions`, `Documents` (Cases НЕ
плутати зі Справами — це тікети підтримки; ховаємо, щоб не збивало).
Що з цього реально є у Free — те й ховаємо; чого нема, того й не буде.

### 6.3. Головний екран (Home)

На вкладці Home → `Customize Home Page` (олівець/⋮):

- компонент **My Open Tasks** (Мої відкриті задачі)
- компонент **Today's Events / My Meetings** (Зустрічі та засідання)
- компонент **Pipeline / Справи за етапами** (funnel по Stage)
- прибрати продажні віджети (Revenue, Target тощо).

Кожен користувач налаштовує свою Home окремо (це персональне подання).

### 6.4. Зустрічі та судові засідання

- Судове засідання = **Meeting (Event)** у CRM, прив'язане до Справи
  (у записі Справи → Open Activities → New Meeting). Тоді на картці
  справи видно всю історію засідань.
- `Calendar → Settings (у самому календарі)`: робочий тиждень Пн–Пт,
  нагадування за замовчуванням (email + push у мобільному застосунку).
- Синхронізація з Zoho Mail Calendar доступна; з Google Calendar у Free —
  обмежена, поки не потрібна.

### 6.5. Пошта

Оскільки пошта вже на Zoho Mail, у CRM можна підключити свою скриньку:
`Settings → Channels → Email → Zoho Mail / IMAP`. Якщо у Free ця
інтеграція виявиться закритою (Zoho періодично міняє межі тарифів) — не
критично: працюємо поштою окремо, а важливі листи фіксуємо нотатками
у Справі.

## Крок 7. Бібліотека бланків у Zoho Writer

Zoho Writer безкоштовний (в межах Zoho Workplace Free / WorkDrive 5 ГБ).

1. Відкрийте `writer.zoho.eu` (або `.com`) під тим самим акаунтом.
2. Створіть структуру папок (у WorkDrive / My Folders):
   ```
   Бланки LEGIUS/
   ├── 01 Договори (договір про правову допомогу, додатки)
   ├── 02 Процесуальні (позовні заяви, клопотання, відзиви, скарги)
   ├── 03 Адвокатські запити
   ├── 04 Довіреності та ордери
   └── 05 Внутрішні (акти, рахунки, звіти клієнту)
   ```
3. Кожен бланк — документ Writer зі змінними-плейсхолдерами в тексті у
   стилі `{{ПІБ_КЛІЄНТА}}`, `{{НОМЕР_СПРАВИ}}`, `{{ДАТА}}` — поки що
   заповнюються вручну (Find & Replace) або через Claude.
   **Mail Merge з CRM свідомо не чіпаємо** (платна фіча) — плейсхолдери
   зробимо сумісними, щоб пізніше ввімкнути merge без переробки бланків.
4. Розшарити папку на всіх трьох партнерів (Share → email партнерів,
   права Edit).

## Крок 8. Конектор Zoho CRM у claude.ai

Anthropic має офіційні Zoho-конектори (CRM, Books, Desk, Projects) у
каталозі Connectors.

1. На claude.ai: **Settings → Connectors** → знайти **Zoho CRM** →
   **Connect**.
2. Пройти OAuth: увійти в Zoho під своїм акаунтом → дозволити доступ.
   (Конектор поважає права користувача Zoho — Claude бачитиме те саме,
   що й ви.)
3. Після підключення в чаті Claude можна: шукати справи й контакти,
   створювати/оновлювати записи, підсумовувати стан справ, готувати
   списки задач — просто текстом: «покажи мої справи на етапі Суд»,
   «створи задачу по справі Іваненко: подати апеляцію до 05.08».
4. Конектор працює лише в чатах, які ви починаєте (тригерів/автоматики
   немає) — для автоматики буде Worker від сесії сайту.
5. Кожен партнер підключає конектор у своєму акаунті claude.ai окремо.

## Крок 9. Мінімальне наповнення для старту

Щоб CRM «завелась», у першу сесію роботи внести:

1. 5–10 поточних активних справ (Справи + Контакти до них) на реальних
   етапах.
2. Найближчі судові засідання як Meetings, прив'язані до справ.
3. По 2–3 відкриті задачі на партнера з дедлайнами.

Після цього тиждень працювати тільки з CRM-задачами — головний ризик
не технічний, а звичка.

## Крок 10. API-дані для сесії сайту (форма → CRM)

Коли кроки 1–5 виконані, підготувати для сесії сайту (Cloudflare Worker):

1. `api-console.zoho.eu` (той самий ДЦ!) → **Add Client** →
   **Self Client** (найпростіше для server-to-server).
2. Отримати **Client ID** і **Client Secret**.
3. Згенерувати grant code зі scope:
   `ZohoCRM.modules.leads.CREATE` (мінімально достатній — Worker лише
   створює Заявки).
4. Передати в сесію сайту: Client ID, Client Secret, grant code (живе
   кілька хвилин — генерувати в момент передачі) або вже обміняний
   refresh token, і позначку дата-центру (`.eu`/`.com` — від нього
   залежить `accounts.zoho.*` і `www.zohoapis.*` у Worker).
5. Секрети НЕ комітити в репозиторій — лише в Cloudflare Worker Secrets.
6. ⚠️ Технічний нюанс для Worker: після перейменування значень списків
   Zoho зберігає старі **actual_value** англійською. При створенні записів
   через API треба передавати саме їх, а не українські назви з інтерфейсу:
   - Справи, поле `Stage`: Консультація=`Qualification`,
     Договір=`Needs Analysis`, Провадження=`Value Proposition`,
     Суд=`Id. Decision Makers`, Виконання=`Proposal/Price Quote`,
     Закрито (успішно)=`Closed Won`, Закрито (відмова)=`Closed Lost`.
   - Заявки, поле `Lead_Status`: перевірити actual_value через
     `GET /settings/fields?module=Leads` перед використанням.
